The local deterministic provider reports zero tokens and zero cost because it performs no external model call. M15 benchmark and demo figures are local deterministic measurements from this development machine, not production capacity guarantees. M15’s 28 scenarios include real end-to-end remote task samples, while the 100-agent/1,000-task scale cases intentionally measure bounded dispatch/coordinator throughput rather than claiming 1,000 simultaneous production workers. Benchmark figures are local measurements from this development machine, not production capacity guarantees. M10 materially reduced measured lookup and routing latency in its workload but increased synchronous write latency; task completion remained unchanged, so no learning-quality improvement is claimed. M11 measurements cover registry and MCP tool-call overhead, not 1,000 full multi-agent executions. SQLite shifts work into native/system CPU, and the asynchronous runtime learning queue is an in-process durability optimization rather than a distributed delivery guarantee. The API and MCP HTTP launcher bind to loopback by default; when `HELIX_API_KEY` is configured, API non-health routes require bearer authentication, and request bodies plus per-client request rates are bounded. CI not run; local verification passed.

## Release gates still required

A production release still needs authenticated API/MCP deployment, TLS termination, actor identity propagation, secret-manager integration, durable/shared MCP audit and rate-limit state, SQLite backup/restore and filesystem-permission review, distributed outbox design if learning durability must survive process loss, distributed swarm snapshot/graph persistence and multi-host membership coordination, shared scheduler/lease authority, production autoscaling signals, federation transport authentication and peer identity, distributed outbox/idempotency, shared peer key rotation and revocation, fencing/clock-skew/partition tests, handoff and rebalancing chaos tests, Docker daemon/image provenance review, seccomp/AppArmor policy review, signed images, sandbox chaos tests, MCP isolation tests with external clients, federation authentication tests, chaos tests against real worker processes, OpenTelemetry exporters, remote database/vector adapters, independent review of application-level consensus assumptions, and human review of policy definitions. Docker integration was explicitly skipped in this environment because no Docker daemon is available; Docker policy generation and availability detection were tested instead. These are explicit capability boundaries in [`capability-boundaries.md`](capability-boundaries.md), not hidden stubs.
