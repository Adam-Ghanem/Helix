# Milestone 8 — Real Execution Sandbox

## Scope

M8 adds a real execution-isolation subsystem to Helix. It does not replace the existing policy engine or runtime. Instead, it adds a typed `SandboxManager` that selects a local or Docker backend, validates commands before launch, records lifecycle evidence, and cleans up temporary execution environments.

## Architecture

```text
Agent / Execution request
          |
          v
Policy + RBAC boundary
          |
          v
SandboxManager -----> SandboxAuditLog
     |                         |
     +----------+--------------+
     |          |
     v          v
LocalSandbox  DockerSandbox
     |          |
     +-----+----+
           v
       Execution result
           |
           v
      Event / audit store
```

## Local backend

`LocalSandbox` uses `spawn(command, args, { shell: false })`. It enforces the executable allowlist, canonical working-directory boundaries, denied paths, symlink-aware existing-path checks, environment filtering, timeout termination, process-group cleanup, and deterministic destroy semantics. It reports that kernel-level filesystem, network, cgroup memory, CPU, and PID limits are not available from this backend. Local mode is suitable for development and deterministic unit tests; it is not equivalent to a container boundary.

## Docker backend

`DockerSandbox` creates a dedicated container and executes commands with the following defaults:

| Control | Behavior |
|---|---|
| Privilege | `--cap-drop ALL`, `--security-opt no-new-privileges`, never `--privileged` |
| User | Configurable non-root user, default `1000:1000` |
| Root filesystem | Read-only by default; only the configured workspace is mounted read/write |
| Network | `none` by default; enabled only when the policy explicitly requests it |
| Resources | Docker `--memory`, `--cpus`, and `--pids-limit` flags |
| Processes | `nproc=1:1` ulimit when child processes are disabled |
| Cleanup | `docker rm --force` on destroy and `docker kill` after timed-out exec |
| Dangerous mounts | No Docker socket mount is generated by the backend |

Docker is optional for normal tests. `dockerAvailable()` detects a usable daemon so CI can skip Docker execution cleanly when no daemon is present.

## Policy flow

The manager applies policy before execution. It checks the executable, canonicalizes the working directory, rejects denied and escaping paths, checks path-like arguments, filters environment keys against an allowlist, clamps command timeouts to the policy ceiling, and records an audit event. Raw environment values are never persisted in the audit log.

## Runtime integration

`ExecutionInput.sandbox` is optional. Existing executions remain unchanged when it is absent. When enabled with a command, the runtime creates and starts a sandbox, executes the command through the manager, emits sandbox lifecycle events, includes the result in the execution result, and destroys the sandbox in a `finally` block. The policy boundary remains authoritative.

## CLI and API

The CLI exposes `helix sandbox doctor`, `helix sandbox run [options] -- <command> [args...]`, `helix sandbox status`, and `helix sandbox destroy <id>`. The API exposes `GET /api/v1/sandboxes`, `GET /api/v1/sandboxes/:id`, and `POST /api/v1/sandboxes/:id/destroy`; execution creation forwards a typed `sandbox` request.

Example:

```text
helix sandbox run --timeout 10s --memory 512 --network none -- node script.js
```

## Security review

The implementation does not interpolate commands into a shell. Docker arguments are constructed as an argv array. Default network access is disabled, privileged mode is never emitted, and the Docker socket is never mounted. Environment values are passed only to the child process and are represented in audit data by allowlisted key names. Path checks use canonical existing paths where possible and lexical containment for paths that do not yet exist.

The remaining deployment gates are kernel/container runtime hardening, secret-manager integration, signed images, seccomp/AppArmor policy review, Docker daemon isolation, and threat-model review. These are not silently represented as complete by M8.
